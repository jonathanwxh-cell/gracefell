App: GRACEFELL, boss-arena souls-like. https://gracefell.alyoechosys.dev · port 8491 · service `gracefell` · repo jonathanwxh-cell/gracefell (public).

## This is a mobile-first game
Design for a 390×844 phone held in two hands, then let desktop inherit. Any new UI has to be
reachable by a thumb, sized for a fingertip (r ≥ 22px), and clear of the joystick half and the
safe-area insets. Desktop/keyboard support is kept because it costs nothing — but it is the
secondary path, and no feature should require a keyboard.

## Layout
- Vite + React + TS app. Game logic lives almost entirely in `src/game/engine.ts` (+ `src/game/audio.ts`). `src/pages/Home.tsx` mounts the canvas and its focus-revealed semantic companion controls.
- `server.mjs` — zero-dep static server for `dist/`, binds **127.0.0.1** (never localhost), SPA fallback, `/health`.
- `qa/verify.cjs` — the Playwright gate. Run before claiming DONE.
- `PROVENANCE.md` / `scripts/provenance.sh` — the multi-agent ledger and its regenerator.

## Deploy loop
1. Change the scoped source or documentation and update `PROVENANCE.md` + `DESIGN.md`.
2. `npm run lint`, `npm run build`, and `npm run qa` — all MUST pass.
3. Publish through a reviewed GitHub PR and identify the exact merged SHA.
4. On the host, fast-forward `/home/alyosha/apps/gracefell` to `origin/main` and run
   `npm --prefix /home/alyosha/apps/gracefell run build`.
5. Restart in an isolated command with `systemctl --user restart gracefell.service`. The
   `restart_service` helper is not available in the ordinary SSH shell.
6. Verify `systemctl --user is-active gracefell.service`, the remote Git SHA, `/health`, and the
   public URL. For gameplay changes, rerun `qa/verify.cjs` with `GRACEFELL_URL` set to production.

The default QA result and screenshots live under the platform temp directory's `gracefell-qa`
folder. Named release runs may set `GRACEFELL_QA_DIR` / `GRACEFELL_QA_RESULT`; repo-local
`.artifacts/` is ignored. The v2.10 evidence contract is documented in
[`docs/releases/v2.10.md`](docs/releases/v2.10.md).

## Don't-undo list
- `window.__game` debug hook — QA depends on it.
- **`qa/perf.cjs` asserts op COUNTS, not durations, on purpose.** Canvas call counts for its pinned scene are identical on every machine; frame timings on this codebase drift ±20% run to run, which is why the v2.20 weather budget (0.5 ms median delta from single `render()` calls) cannot actually detect what it asserts. Do not "improve" the gate by converting it to a time budget. The load-bearing assertion is the *slope* — the scene is censused with 32 projectiles and again with none, and gradients-per-projectile must stay ≤ 1.2 — so a new per-entity gradient trips it even while the absolute count still fits. Keep the two-consecutive-frame determinism check: it is what caught a lazily-built cache that allocated only on its first frame.
- **Do not re-attempt the v2.23 render optimisations without on-device evidence.** Pre-baked glow sprites for particles were measured **17.6% slower** (non-overlapping IQR, interleaved against a same-build control at +0.5%). A projectile-glow sprite (−1.5%/−3.5%), offset double-draw instead of `shadowBlur` (−1.4%), and a baked static vignette (+1.9%) were all inside the noise floor. A worst-case phase-three frame is ~1.7 ms of a 16.7 ms budget: **the draw path is not the constraint.** Do not gate visual work on making it cheaper. If you must measure, serve the variants simultaneously and alternate measurement blocks between them, and always measure a second copy of the same build as a control — sequential measurement of one build at a time cannot separate signal from drift here. Micro-benchmarks in tight loops saturate the fill pipeline and gave three contradictory answers, including a `drawImage`/`fill` relationship that inverts between headless software raster and a real GPU.
- Baked floor (`buildFloor`) + scorch canvas: floor detail is rendered ONCE offscreen. If you add floor detail, add it inside `buildFloor`, not in `drawArena` (per-frame).
- v2.25 defaults to the Blender-authored cached arena plus `blender-canvas` Malakar. `?visual=procedural&boss=current` is the exact Classic comparison/fallback; `?boss=blender-three` is a query-gated development proof, not the production default. The arena copies into a replacement floor and swaps only after success. Late base assets wait for title/intro/pause/reset, late phase masks wait for another authored phase boundary, and asset/upload/WebGL failure must retain Canvas without changing simulation.
- Versioned `/art/?v=...` requests are immutable in production; unversioned art is intentionally `no-store` because Cloudflare's default four-hour browser TTL overrides `no-cache` for static extensions. `src/game/render/visualModes.ts` owns `VISUAL_ASSET_VERSION`; bump it whenever a shipping WebP or GLB changes. Keep arena/phase/GLB budgets and stable Malakar node names locked by `scripts/art/validate_assets.mjs`, and keep the strict visual lane in `qa/run.cjs`.
- Missing `/assets/`, `/audio/`, and `/art/` files return `404 no-store`; never route a static miss to `index.html`, because the requested static prefix would otherwise make fallback HTML immutable.
- Compact touch clear-tell/chain cues occupy the boss-title lane while active. Do not float them above the boss HUD: native-size review found that placement covered the player's lower silhouette during the ring dodge decision.
- First-interaction timing separates native `AudioContext` construction from code-owned graph work. Isolated v2.24/v2.25 A/B showed the native constructor consumes 93–94% and varies across hosts. Keep `graphInitCostMs <= 8 ms` and the 40 ms total stall guard; do not restore a non-portable 20/25 ms total threshold or move visual loading into the gesture. The visual loader starts 120 ms later, and visual QA records a trusted-event microtask before timers.
- Phase weather is renderer-only and fixed at 64 motes: 48 low-alpha background motes above the cached floor but below every telegraph/entity/hazard, plus 16 edge-only foreground motes below the HUD. `weatherForPhase()` owns Quiet Ash / Ember Gale / Gracefall Storm, transitions use the paused game clock, and flash-reduced or shake-disabled play uses the 0.45 motion scale. Do not add a second particle pool, full-screen blur/fog surface, weather timer, runtime asset, or continuous wind audio loop.
- Particle/projectile bloom uses `globalCompositeOperation = 'lighter'` inside save/restore pairs — keep the restores or everything turns additive.
- **v2.24 impact frames are presentation only, and `qa/v224.cjs` enforces that.** The player's attack stretch is applied to the transform *around* `drawKiteVeilBody`, never to the authored path data — the seven `design-qa.md` macro-silhouettes must keep surviving the 0.55 mobile camera. `Boss.recoil`/`recoilAng` displace the **drawn body only**; the shadow stays planted and `boss.x/y` never move, because a visual knockback that feeds back into position changes hit geometry. The lane also renders three times per simulation step across a live swing and fails if any simulation field changes — both effects add draw-time logic, and the way that goes wrong is a render path writing back into state. `attackStretchImpulse` is a pure exported fn locked by `engine.test.ts`; tune the curve there, not at the call site.
- `resetFight` must clear the scorch canvas (setTransform reset → clearRect → restore) — the ctx carries a center translate.
- localStorage key `gracefell` — schema **v7**: `{v, bestTime, bests{}, wins, lastScore, bestScores{}, scoreHistory[], attempts, muted, musicVolume, sfxVolume, grace, shakeEnabled, flashReduced, hapticsEnabled, leftHanded, tutorialComplete}`. `leftHanded` defaults false for older saves. `lastScore` and each `bestScores[grace]` entry preserve `{grade, time, trial, attempt, damageDealt, woundsTaken, perfectDodges?, flasksUsed?, oathRank?}`. `scoreHistory` retains at most 20 of those scorecards newest-first plus `completedAt: ISO-string | null`; `null` is the honest v5 migration for an undated legacy last score. Bump `Game.SAVE_VERSION` and add a migration branch in the constructor if you change it; QA proves v7 settings, scores, and handedness round-trip while all earlier migration contracts remain intact.
- `bests[grace]` is authoritative for records; top-level `bestTime` is only the migrated grace-0 display fallback. Never show a global PB as another trial's record.
- Phase-3 transition intentionally resets all boss cooldowns.
- **The reserved hazard hue.** `PAL.danger` / `PAL.dangerEdge` mean one thing: this will hurt you. Hostile projectiles, hostile rings, attack telegraphs — nothing else. Decorative fire uses `PAL.amber`. A QA assertion fails if any ambient particle carries the danger hue. If you need a new warm colour, add one; do not borrow this one.
- Hazards are also **shape-coded** so they survive colour blindness: projectiles get a white core + rotating diamond (decor is round), hostile rings get a bright leading edge, meteors get four inward ticks. Keep the redundancy — colour alone is not a signal.
- `difficultyForGrace()` is the single derivation point for every difficulty/accessibility lever. It is a **pure exported module function** (the `Game.difficultyForGrace()` method delegates to it) and is locked by `src/game/engine.test.ts` — if you change the −3..+5 curve, update that test. `resetFight()` snapshots it into `trialMods`, and `Game.mods` serves that immutable snapshot outside the title. Do not tune at call sites or allow the title/semantic dial to mutate an intro/fight.
- Pure helpers and the save-schema validator (`clamp`, `lerp`, `seededRandom`, `difficultyForGrace`, `isVictoryScore`, …) have Vitest unit coverage in `src/game/engine.test.ts`. `npm test` runs it; CI runs it before the Playwright gate. The engine's render methods are declared on the `export interface Game` merge and assigned to `Game.prototype` (no `as any`).
- Negative paths are Grace and positive paths are Oaths. Named boss-windup text is exclusive to -3/-2. Oath packets may only compose swipe, slam, charge, and volley; never add ring, meteor, or spiral to a packet because stacked area denial is not the mastery contract. Oath I/II schedule at most one follow-up, Oath III/IV increase frequency/recovery pressure at the same cap, and Oath V may schedule two. Clear the queue on phase transitions and stagger, and keep `OATH CHAIN step/total` truthful.
- Touch boss tells have authored reaction floors: 300 ms for a fresh windup and 240 ms for a swipe follow-up. `Boss.currentWindup` is shared by combat and rendering. Keep projectile/ring travel speeds fixed and do not reconstruct the visual duration from phase/speed.
- +3/+4 poise is harder but breakable (162/204, with 1.45/1.25 s openings). No-stagger is exclusive to FORSAKEN +5 and must remain disclosed by the `IRONBOUND` HUD plus locked poise bar.
- `touchLayout()` is the single source of truth for the on-screen controls — renderer, hit-test and QA all read it. It mirrors the complete action cluster when `leftHanded`; `Input.leftHanded` mirrors joystick acquisition, and tutorial/help copy follows the same preference. Buttons are placed in `base` units and the whole cluster shrinks on narrow screens; don't reintroduce fixed pixel offsets.
- `playerHudRect()` protects the Canvas-drawn HP, stamina, and flask lane. On compact screens MENU, MIX, PAUSE, and the Canvas SOUND target share the 44px utility rail returned by `combatUtilityTop()`; the compact DOM CSS mirrors that top coordinate. Keep the cross-layer QA collision assertion when changing any of those controls — per-element viewport checks did not catch MIX covering the iPhone HP bar.
- Roll slash is a buffered post-roll verb: ATK during `roll` sets `rollSlashQueued`, but never shortens `rollIframes` or the 0.42 s dodge. FLANK is a rear arc beyond 110°, disabled during windup/stagger, with 1.25× damage and 1.5× poise pressure; do not stack it with EXECUTE.
- Terminal mastery telemetry is run-local and presentation-only. `damageMix`, `phaseEnteredAt`, and the last three received hits reset in `resetFight`; they must not alter grading or combat. Victory REMAIN/ASCEND requires the established 4.5 s fresh-input hold; Ascension moves exactly one path step and never silently changes the completed score.
- Player pause uses `manualPaused` as a separate owner from focus and browser-interruption pause. `syncPauseState()` ORs those owners so a focus/visibility resume cannot cancel a deliberate pause. The persistent DOM control is 76×44px beside SOUND, P/Escape use the same transition, and resuming clears input buffered while the pause card was open.
- Battle MENU is available after leaving the title and uses `uiFocused` as its pause owner. In a live fight it suspends simulation and audio, traps focus, removes the canvas and background controls from the tab order, and clears combat input before resume. `Game.returnToTitle()` abandons only the current run: it must not increment attempts/wins or erase saved results/settings. The title SCORES dialog is DOM, capped to the latest 20 local victories, restores focus to SCORES, and must remain within 390×844 without page overflow.
- `Game.uiSnapshot().combat` is the semantic bridge for health, stamina, flasks, boss health/phase/poise/action, combo hits, and queued lights. Keep changing numeric resources in the non-live `<dl>`; only meaningful state, phase, and telegraph changes belong in the polite live status or screen readers will be flooded every 250 ms.
- `Input.isTouch` is seeded from `coarsePointer()` at construction, NOT from the first touch event. Before this, phone users saw "CLICK TO RAISE YOUR BLADE" and a line of WASD bindings as their first impression. Keep the up-front detection.
- Terminal retry/replay uses `Input.confirmSequence`, a monotonic gesture counter snapshotted on death/victory. Do not replace it with only the short combat buffer: pointer-only embedded browsers and focus handoffs can otherwise discard the visible “rise again” tap. Victory deliberately discards confirmations during its 4.5-second scorecard hold and requires one fresh input after the replay prompt appears.
- `Receive Grace` is an explicit repeated-death offer, never hidden dynamic difficulty. It lowers the selected path by one step and snapshots the current `confirmSequence`; the offer gesture must not retry behind itself. Lethal-source hints depend on propagating `DamageSource` through every hostile hit path.
- Safe-area insets come from `--sa-b` / `--sa-r` published in `src/index.css` and read in `resize()` — `env()` isn't reachable from a canvas context.
- `menuGeom()` is the single source of truth for title-menu layout — renderer, hit-test and QA layout assertions all read it. If you move a menu element, move it there or the test stops protecting you.
- `shake()` early-returns when `shakeEnabled` is false, and `flashScale()` gates full-screen flashes. Don't bypass them with direct `shakeAmp` writes — they're photosensitivity controls, not polish.
- Perfect dodge window scales with grace: `t > 0.42 - 0.24 * mods.perfectWindow`; `perfectCd` prevents multi-trigger from one swing.
- Rapid light input uses `Player.queuedLightAttacks`, a capped two-entry follow-up queue. It exists
  because the generic TTL flag cannot distinguish repeated taps during one attack. Keep it
  light-only, clear it on roll/heavy/damage/combo expiry, and preserve roll priority at the next
  transition. The step-2 light finisher must use the light SFX family; HVY alone owns heavy cues.
- Visible player-chain feedback counts connected light hits, not presses. Misses, heavy, roll,
  damage, and expiry clear it; the third connected hit owns the `LIGHT FINISHER ◆◆◆` read. Keep
  the screen-space feedback away from the phone action cluster and do not use it to drive combat.
- Queued light inputs are still presses, not connected hits: render them as `INPUT QUEUED` or
  `NEXT` diamonds without adding them to the hit chain. This acknowledgement is what keeps rapid
  touch input from feeling lost while preserving the connected-hit scoring contract.
- `GameAudio` owns synthesis, soundtrack loading, player-relative distance/pan, arena reverb, adaptive music, ducking, limiting, voice pressure, scheduling and teardown. Gameplay code should name the event and pass `audioSpatial(x, y)`; it should not build Web Audio nodes itself.
- `public/audio/sfx/` is the v2.22 recorded-foley library. Runtime admits exactly 45 cues through `SFX_MANIFEST`: 15 critical, 24 phase, and 6 cosmetic. The documented weak alternates `dodge-2`, `near-miss-2`, `player-step-1`, `swing-2`, and `swing-3` are provenance/A-B material only and must not enter runtime rotation. Keep exact hashes, mastering truth, and exclusions in `public/audio/sfx/README.md`; bump `SFX_VERSION` whenever a shipped runtime MP3 changes.
- Recorded cues are a hybrid texture layer, never the only voice for a gameplay-significant event. The bounded loader uses at most four workers, drops to three on lower-core devices and two for Save-Data/2G, loads the complete critical tier before phase/cosmetic work, and keeps synthesis available on cold start, fetch/decode failure, or held-back cues. Do not prefetch/decode the 45-file library before the first user gesture or replace it with unbounded `Promise.all`.
- `chargeLoopStart` / `chargeLoopSet` / `chargeLoopStop` own the single sustained charged-heavy voice. It must deduplicate repeated starts and stop on release, player damage, reset/retry, title return, death, victory, and `destroy()`. Recorded boss charge scrapes are grains, not this sustained voice; keep their engine cadence at or above 0.36 seconds so the 0.6-second tails do not flood the limiter.
- Bass-led recordings such as execution, boss steps, meteors, roars, slams, and death are support bodies. Their short 1–5 kHz `phoneTransient` partners preserve contact on mono phone speakers. Keep those partners restrained and critical-voice-reserved; do not blanket-EQ or stack a second full procedural effect behind every sample.
- `GameAudio.queueContextState()` serializes asynchronous `AudioContext.suspend()` / `resume()` reconciliation. Keep it as the single state-transition path: a fast MENU close followed by manual pause can otherwise let the older resume promise win and restart audio under a paused game.
- `public/audio/gracefell-phase-{1,2,3}-*.mp3` are the three MiniMax Music 3.0 phase masters. Two permanent `HTMLAudioElement` / `MediaElementAudioSourceNode` decks swap sources and stream through `deck gain -> soundtrackPresenceDip -> soundtrackFilter -> soundtrackMusic -> music -> master`; phase changes wait no more than 250 ms for a 78 BPM beat, then crossfade for 720 ms. Playback rejection must retain and retry the requested phase without growing the node graph or promoting a paused deck; procedural drone/drums remain the network/playback fallback. Do not return to decoding full tracks into `AudioBuffer`s on mobile.
- Noise data, arena-IR data, and the static peak-limiter curve are generated once in the first zero-delay preparation task. Noise and IR data are copied into their Web Audio buffers together in the next task after the first gesture unlocks the context. Tone and recorded/procedural sample fallbacks remain available during that sub-frame handoff. Keeping the buffer copies and limiter-curve math outside synchronous `init()` protects the strict first-gesture budget; do not return to allocating/filling an `AudioBuffer` for every projectile or impact — phase-three storms make that a mobile GC problem.
- Boss windups use `audio.telegraph(attack, spatial)`. The seven attack names are an audio readability contract: a player should be able to distinguish swipe, slam, charge, volley, meteor, ring and spiral before the hit lands.
- Combat owns the mix: keep SFX at full submix gain, the music bus at or below 0.24, the soundtrack submix at or below 0.56, and the broad 1.8 kHz soundtrack dip at least 4 dB deep. Player verbs and all seven boss windups must use critical voice reservations and stack-safe duck requests where the strongest active request wins. Keep Music and Combat effects separately adjustable and persisted. The MIX modal may pause simulation while leaving audio audible, but it must trap focus, disable background pause/canvas input, and let Done, Escape, or the backdrop clear combat input and resume safely; MIX stays disabled during a player-owned manual pause. Bump `SOUNDTRACK_VERSION` whenever any MP3 changes so browser/CDN caches cannot retain an older score.
- `vary()` is the central SFX anti-repetition policy. Keep hostile telegraph timing exact; apply variation to performance and impact sounds, and retain repeat masking/critical-voice reservations rather than adding unbounded layers at call sites.
- The generated score, procedural drone, drums and tension pad have separate submix gains. `updateCombatState()` owns low-health, boss-intensity and stagger transitions. The master route must remain `master -> compressor -> peakLimiter -> destination`.
- The arena IR sample data is prepared once in the first zero-delay preparation task and copied into its Web Audio buffer on startup. It should stay above 1.5 seconds while the measured first-gesture buffer build remains below the QA budget. Distance processing owns attenuation, low-pass and room-send changes together; do not add call-site volume hacks.
- Prepared noise/IR data uses a 24 kHz canonical rate, but the runtime AudioBuffers must be resampled to `AudioContext.sampleRate`. Chromium may open at 44.1 kHz and rejects a mismatched convolver buffer before the fight can start. The arena response remains at least 1.5 seconds and is mono after the already-stereo spatial send to keep cold allocation inside the mobile budget.
- Boss stalk footsteps and charge scrape are state foley. Charge scrape must stop with charge state; it is intentionally requested in short grains rather than held as an orphanable looping node.

## Headless QA facts (hard-won)
- Playwright is a repo dev dependency. `npm run qa` starts an isolated fixed-port server and uses Playwright's installed Chromium; `PLAYWRIGHT_CHROMIUM_PATH` remains available for unusual hosts.
- Constructing a second `Game` (e.g. to test save migration) **overwrites the `window.__game` hook**, and `destroy()` does not restore it — every later assertion then silently reads a dead instance. Save and restore it around the construction.
- Semantic path controls have a post-launch regression: pointer **More Oath** and keyboard **More Grace** must change exactly one step, keep `state === 'title'`, and leave the canvas `confirmSequence` untouched before semantic Start begins the selected run. Coordinate-based browser automation can otherwise misreport a click through the hidden/revealed companion as a canvas action.
- Screenshots are not always reviewable by an agent. When they aren't, make correctness numeric instead of eyeballing: that's why `menuGeom()` exists and why the layout assertions caught a chevron drawing 5px outside its plate at 390px.
- Headless RAF timing varies → gate on `waitForFunction(game.stateT/state)`, never wall-clock sleeps, for sim-time thresholds.
- Boss ignores damage while `state === 'spawn'` (intro). Wait for `game.state === 'fight'` first.
- AudioContext works headlessly but is silent. QA asserts initialization, MiniMax MP3 decode, limiter/noise-pool presence, voice pressure, every boss-cue code path and haptic requests; actual timbre and mix balance still require a listening pass on phone speaker + headphones.

## Known scope edges
- Touch is genuinely tested: `qa/verify.cjs` runs a third `hasTouch + isMobile` pass that taps to start, verifies +5 swipe floors/visual timing and IRONBOUND disclosure, drives a real drag, completes a visible three-hit ATK chain with queued-input acknowledgement, checks button and MENU geometry, dies naturally, proves touchscreen and pointer-only resurrection, receives Grace without retry leakage, and reloads a timestamped victory score. The desktop/mobile lanes also exercise the battle-menu freeze/resume/return flow, empty and populated score dialogs, semantic combat telemetry, keyboard-focus reveal, live MIX auditioning, safe dismissal, separate volume persistence, stack-safe duck expiry, rapid audio-owner handoff, pause-during-crossfade, rejected phase playback, permanent-deck node stability, save-v6 round-trip, and v5 score migration. Dedicated Journey tell, Oath chain, combo finisher, Grace death, FORSAKEN title, IRONBOUND, and score-dialog captures guard the UI.
- Still unverified by machine: haptics (no vibration API headless) and real iOS Safari URL-bar / dvh behaviour.
- `npm ci` installs deterministically from the committed lockfile (verified in v2.16). Keep the lockfile in sync when you change dependencies (`npm install`, then commit `package-lock.json`).
