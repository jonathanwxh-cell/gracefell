Date: 2026-07-25
Owner: @jonathanwxh-cell

Implementation and verification: Codex with audio runtime, gameplay integration,

Status: locally accepted release candidate; production receipts pending

## Outcome

Gracefell now uses a compact recorded-timbre combat library without making
network delivery a gameplay dependency. Forty-five accepted MP3 cues add
authored body and texture to player actions, boss tells and releases, impacts,
movement, phase changes, healing, execution, death, and recovery. Every
gameplay-significant cue retains a synthesized path for the cold start, a failed
request/decode, or a deliberately held-back recording.

This release does not change combat timing, damage, stamina, invulnerability,
boss AI, difficulty, weather, phase music, scoring, controls, touch geometry,
save schema v7, or persistence.

## Why the supplied archive was not copied blindly

The supplied library contained fifty valid 44.1 kHz mono MP3s, but file validity
was not the same as production readiness:

- five alternates were weaker or less distinctive than their companion takes;
- several large dramatic cues placed 89–100% of measured energy below 250 Hz
  and lost their action edge on a phone speaker;
- the charged-heavy loop needed explicit gameplay lifecycle ownership;
- a roughly 0.6-second charge scrape could stack seven tails under the old
  90-millisecond procedural cadence;
- loading and decoding every file in one gesture would violate the existing
  mobile first-touch contract;
- replacing synthesis outright would make cold or failed delivery silent.

The accepted solution is therefore a hybrid recorded-body/procedural-fallback
system rather than an all-sample replacement.

## Asset acceptance and mastering

All fifty supplied files decode as 44.1 kHz mono MP3. The runtime ships the
forty-five accepted cues; it preserves but never rotates these five weak
alternates:

- `dodge-2`;
- `near-miss-2`;
- `player-step-1`;
- `swing-2`;
- `swing-3`.

Codex changed only four masters:

| Cue | Justified correction |
| --- | --- |
| `charge-loop` | reduced true peak/sub dominance and added a conservative circular 20 ms loop crossfade |
| `ring-release` | reduced true peak/sub dominance while restoring usable 1–5 kHz presence |
| `swing-1` | reduced true peak and extreme sub dominance while restoring usable 1–5 kHz presence |
| `swing-heavy-2` | reduced true peak and restrained sub dominance |

Blanket re-encoding was rejected because the supplied masters were already
lossy. The remaining Kimi masters are byte-preserved. Exact duration, LUFS-I,
dBTP, byte count, SHA-256, prompt text, processing details, before/after
measurements, and exclusions are authoritative in
[`../../public/audio/sfx/README.md`](../../public/audio/sfx/README.md).

## Runtime contract

### Priority and worker bounds

`SFX_MANIFEST` contains exactly 45 entries:

- 15 critical;
- 24 phase;
- 6 cosmetic.

Order is semantic. The complete first-fight vocabulary loads before later-phase
and cosmetic texture. The worker limit is:

- 4 normally;
- 3 on devices reporting four or fewer logical cores;
- 2 when Save-Data, 2G, or slow-2G is reported.

The loader starts in a task after the first user gesture. It uses
`AbortController` plus a generation token so a replaced or destroyed
`AudioContext` cannot publish stale decoded buffers. `SFX_VERSION=2.22.0`
versions every URL; the server's existing immutable `/audio/` policy handles
cache reuse.

### Honest fallback

Exact cue names are tried first. Prefix families use stable round-robin
variation without immediate repetition. If no accepted buffer is ready, the
existing synthesized cue runs. This applies during cold start and any
fetch/decode failure; a recording is never treated as proof that the gameplay
event sounded.

### Phone clarity

Low-frequency bodies such as execution, boss steps, meteors, roars, slams, and
death retain their recorded weight but receive one short, restrained 1–5 kHz
procedural contact edge. This is a presence partner, not a duplicate full
effect. It uses the critical voice reservation where masking would otherwise
make an important action disappear.

### Sustained charged-heavy ownership

Charged heavy owns one sustained voice:

1. start once when the hold enters charge;
2. update gain with charge amount;
3. stop on release;
4. also stop on damage, retry/reset, title return, death, victory, and audio
   destruction.

Repeated starts do not create a second voice. If the loop is not decoded yet,
one band-limited synthesized motor voice provides the same lifecycle.

Boss charge scrape remains a grain rather than a sustained loop. Its gameplay
request cadence is now 0.36 seconds and the audio-level gate is 0.32 seconds,
preventing long recorded tails from flooding the limiter.

### First-gesture work

Noise, room-impulse data, and the static peak-limiter curve are prepared before
a realistic first tap. The first gesture creates only the graph. Copying the
reusable noise and room buffers into the device-rate `AudioContext` happens in
the existing next task; recorded/procedural sample or oscillator fallbacks cover
that handoff.

No acceptance threshold was raised. This sequencing exists specifically to keep
the established 25 ms desktop and 20 ms fast-touch budgets meaningful.

## Gameplay ownership map

| Event | Runtime ownership |
| --- | --- |
| light/heavy swing and hit | recorded family with anti-repeat variation and procedural fallback |
| heavy hold | one deduplicated `charge-loop` voice with intensity and complete cleanup |
| player wound | light/heavy cue chosen after difficulty-adjusted damage is known |
| empty flask | explicit dry cue without consuming another flask input |
| movement / close dodge | throttled step and near-miss texture |
| boss tell | attack-specific `tele-*` cue through existing critical ducking |
| boss release | boss-specific release semantics rather than borrowing player heavy |
| phase boundary | `stamp` plus existing phase/roar behavior |
| stagger execution | explicit execute body plus phone contact edge |
| Receive Grace | ward chime rather than generic UI tick |
| death/victory/reset/title | stop sustained voices before terminal/reset ownership changes |

## Acceptance contract

The complete gate remains `npm run qa`. It runs production build and real
Chromium lanes for desktop, 390×844 mobile, true touch, a fast fresh-touch audio
context, and a constrained Save-Data phone.

The v2.22-specific lane adds a 65 ms delay to every SFX request and forces two
workers. It requires:

- `audio/mpeg`, HTTP 200, and immutable caching for a versioned SFX asset;
- exactly 45 unique `?v=2.22.0` requests with zero duplicates or failures;
- all 15 critical cues ready at the natural fight boundary;
- final state `ready`, 45/45 loaded, zero failed, truthful 15/24/6 tier sums;
- one procedural sustained fallback before samples arrive and a clean stop;
- distinct player-heavy and boss swipe/charge/spiral release routing;
- distinct light/heavy wound routing;
- boss scrape frames separated by at least 20 simulation frames;
- one sample-based sustained voice after load, no duplicate start, and zero
  sustained voices after release, damage, reset, title, or destroy;
- zero console or page errors.

The broader matrix still protects audio context/sample-rate matching, 1.5-second
room response, voice ceilings, music ducking, pause ownership, soundtrack
streaming, desktop/mobile/touch layout, gameplay, persistence, accessibility,
and all earlier release contracts.

## Future-agent cold start

1. Read `AGENTS.md`, the v2.22 section of `DESIGN.md`, this record, and
   `public/audio/sfx/README.md` before changing combat sound.
2. Keep `SFX_MANIFEST`, its 15/24/6 counters, and `SFX_VERSION` aligned.
3. Do not add the five held-back alternates without a new listening and
   measurement pass.
4. Preserve procedural fallback for every important event.
5. Never move network/decode or reusable-buffer copy back into synchronous
   `init()`.
6. Exercise the natural intro boundary under the two-worker/65 ms test, not
   only a warm cache.
7. Treat charged-heavy audio as gameplay state and preserve all teardown paths.
8. Verify GitHub merge, host SHA, service, loopback/public health, versioned
   asset headers, and public full QA separately.

## Rollback boundary

The feature is confined to `src/game/audio.ts`, event calls in
`src/game/engine.ts`, `public/audio/sfx/`, QA, version metadata, and
documentation. Save data needs no migration. A rollback can remove the
recorded manifest/assets and event extensions while retaining the established
procedural audio engine and v2.21.2 gameplay.
