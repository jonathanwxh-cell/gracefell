## Outcome

Gracefell now gets dimensional environment art and a stronger boss silhouette
without replacing its Canvas simulation or adding work to the default frame
loop.

The production treatment is:

- a Blender-authored Ashen Reliquary copied once into the existing adaptive
  cached-floor slot;
- two small transparent masks stamped into the existing scorch surface at the
  authored Phase 2 and Phase 3 transitions;
- a presentation-only Canvas Malakar driven by a read-only snapshot of the
  existing boss state.

Combat geometry, damage, timing, difficulty, input, audio, score, save schema
v7, weather ownership, and semantic UI remain unchanged.

The release also removes `react-router`. Gracefell has one page and used the
package only to map `/` to `Home`; rendering `Home` directly preserves behavior,
reduces the normal bundle, and avoids shipping a known high-severity advisory
when the fixed major requires a newer production Node runtime.

## Parallel work preserved

This branch was based on the newest parallel v2.24 candidate rather than
`origin/main`. It therefore includes and preserves:

- v2.23's deterministic render-operation gate;
- v2.24's tapered sword trail, player swing stretch, boss visual recoil, unit
  coverage, and render-side-effect QA.

The visual-depth work extends those changes and does not overwrite them.

## Runtime boundary

### Cached Canvas arena

The authored base does not add another permanent full-size canvas. It draws
into a replacement surface and swaps that surface into `floorCanvas` only after
the draw succeeds.

Failure behavior is deliberate:

- fetch or decode failure leaves the procedural floor active;
- allocation or `drawImage` failure leaves the old floor untouched;
- a base that finishes during active combat is queued until title, intro,
  pause, or reset;
- phase masks stamp only from `deepenArena()` at a real phase boundary;
- a late phase mask waits for another run instead of appearing during a dodge;
- an overlay draw failure is caught, recorded, and never escapes into combat.

### Canvas Malakar

The accepted boss treatment reads only:

- root position and facing;
- phase, state, and attack;
- windup progress;
- hurt flash and visual recoil;
- halo spent count;
- phase-three second-sword reveal;
- presentation clock.

It does not own or mutate hitboxes, animation time, attack resolution, phase
logic, health, poise, collision, score, or persistence.

### Three.js comparison

`?boss=blender-three` dynamically imports a vanilla Three.js proof, loads the
compressed GLB, renders it to a private 256px offscreen surface, and composites
that result into the existing visible Canvas. It creates no DOM canvas and no
second animation loop.

The proof is not the production default. Native-size player review found the
authored body too dark and visually flattened compared with the Canvas
treatment. The code remains an explicit development comparison only.

GLB failure returns to Canvas and releases the unused WebGL context and scene.
Real WebGL context loss returns to Canvas while retaining the proof for
restoration. The dynamically imported chunk is not fetched by normal play.

## Cache and delivery

`server.mjs` now serves WebP, AVIF, GLB, and glTF with explicit MIME types and
gives versioned `/art/` requests immutable caching. Unversioned art uses
`no-store, max-age=0` plus `Cloudflare-CDN-Cache-Control: no-store`; this is
stricter than revalidation because Cloudflare's zone-wide four-hour browser TTL
otherwise raises `no-cache` on static extensions to `max-age=14400`.
`VISUAL_ASSET_VERSION` is appended to every runtime art request;
changing any shipping WebP or GLB requires a version bump.

Missing `/assets/`, `/audio/`, and `/art/` paths return `404 no-store` instead
of the SPA fallback. This prevents a mistyped versioned static URL from caching
`index.html` as an immutable image, script, or sound.

The final independent mobile capture review also moved clear-tell combat cues
into the compact boss-title lane. `READ · RING` no longer covers the player's
lower silhouette during the dodge decision; desktop keeps its existing
separate cue lane.

## Acceptance contract

The new `qa/visual-upgrade.cjs` lane is part of `npm run qa`. It covers:

- exact asset HTTP status, MIME, dimensions, bytes, and decode;
- `390×844` true-touch DPR2 and `1280×800` desktop captures;
- quiet and severe-weather telegraph boundary sampling;
- HUD and touch-control protection;
- procedural versus baked operation census and permanent-surface inventory;
- corrupted and delayed arena delivery;
- atomic base-application failure;
- late and failed phase-mask stamping;
- current, Canvas, and Three Malakar states;
- corrupt-GLB Canvas fallback and renderer release;
- real `WEBGL_lose_context` loss and restoration;
- render-side-effect checks over gameplay, save, input, and audio state.

### First-interaction timing

Visual loading starts in a later task, 120 ms after the first audio unlock, and
the gesture QA samples a trusted-event microtask before timers can run.
An isolated 30-sample comparison found no v2.25 regression against `8a208bc`:
pooled mean audio initialization was 26.88 ms for v2.25 versus 27.59 ms for the
baseline. Native `AudioContext` construction accounted for 93–94% of the total;
the app-controlled graph took about 1–3 ms.

QA therefore records `contextCreateCostMs` and `graphInitCostMs` separately. An
8 ms graph time remains the engineering target; the single-sample release
ceiling is 12 ms, alongside a 40 ms total native/platform stall guard. This
replaces the non-portable 20/25 ms absolute limit without weakening the part
the application controls.

## Known limits

- Desktop/mobile Chromium automation is not a physical-phone thermal test.
  Recent iPhone, older iPhone, and mid-range Android ten-minute soaks remain a
  device-owner gate before live Three could ever become default.
- The GLB is a static proof with runtime-owned sword/core/halo transforms, not a
  rigged five-pose production character.
- The concept boards under `docs/visual-upgrade/assets/` are design references,
  not runtime textures.
